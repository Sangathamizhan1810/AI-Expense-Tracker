# Plan 01-02: Authentication System — Registration, Login, Session Management & Auth Guards

**Phase**: 1 — Foundation, Database Architecture & Authentication  
**Plan**: 01-02  
**Requirements**: AUTH-01, AUTH-02, AUTH-03, AUTH-04  
**Estimated tasks**: 5

## Objective

Implement the complete authentication flow: secure user registration with input validation, login/logout with Flask sessions, password hashing via Werkzeug, route-level auth guards (`@login_required` decorator), and polished registration/login form templates with modern UI styling.

## Context

- Passwords MUST be hashed using `werkzeug.security.generate_password_hash` / `check_password_hash`
- Flask sessions store `user_id` — each request retrieves the logged-in user
- Complete data isolation: every DB query that touches user data must include `WHERE user_id = ?`
- Auth blueprint pattern keeps routes organized under `/auth/`
- Form validation: server-side with flash messages for errors

## Tasks

### Task 1: Auth Blueprint & User Model Helpers
**Type**: implementation  
**Files**: `auth.py` (or `blueprints/auth.py`)

Create a Flask Blueprint for authentication:

```python
from flask import Blueprint
auth_bp = Blueprint('auth', __name__, url_prefix='/auth')
```

User model helper functions (in `utils/db.py` or `models/user.py`):
- `create_user(name, email, password)` — validates inputs, hashes password, inserts into `users` table, returns user dict or raises
- `get_user_by_email(email)` — fetches user row by email
- `get_user_by_id(user_id)` — fetches user row by ID

Validation rules:
- Name: required, 2–50 characters
- Email: required, valid email format (basic regex), must be unique
- Password: required, minimum 6 characters

Register the blueprint in `app.py`'s `create_app()`.

**Verification**: Blueprint registers without import errors.

### Task 2: Registration Route & Template
**Type**: implementation + frontend  
**Files**: `auth.py`, `templates/auth/register.html`

**Route `POST /auth/register`**:
1. Extract `name`, `email`, `password`, `confirm_password` from form
2. Validate all fields (non-empty, email format, password length ≥ 6, passwords match)
3. Check email uniqueness in database
4. Hash password with `generate_password_hash(password, method='pbkdf2:sha256')`
5. Insert user into `users` table
6. Flash success message: "Registration successful! Please log in."
7. Redirect to `/auth/login`
8. On validation error: flash specific error message, re-render form with preserved inputs (except password)

**Route `GET /auth/register`**: Render `register.html`

**register.html** template:
- Extends `base.html`
- Centered card with "Create Account" heading
- Form fields: Full Name, Email, Password, Confirm Password
- Each input with floating label or placeholder styling
- Submit button with gradient accent styling
- "Already have an account? Sign in" link to `/auth/login`
- Server-side error messages displayed via flash

**Verification**: User can fill out the registration form and submit. Duplicate email shows error. Successful registration redirects to login page.

### Task 3: Login Route & Template
**Type**: implementation + frontend  
**Files**: `auth.py`, `templates/auth/login.html`

**Route `POST /auth/login`**:
1. Extract `email` and `password` from form
2. Look up user by email
3. Verify password with `check_password_hash(user['password_hash'], password)`
4. On success: set `session['user_id'] = user['id']`, set `session['user_name'] = user['name']`
5. Flash success: "Welcome back, {name}!"
6. Redirect to `/` (later will redirect to dashboard)
7. On failure: flash "Invalid email or password", re-render login form

**Route `GET /auth/login`**: Render `login.html`

**login.html** template:
- Extends `base.html`
- Centered card with "Sign In" heading
- Form fields: Email, Password
- "Remember me" checkbox (optional, stretch)
- Submit button with gradient accent styling
- "Don't have an account? Register" link to `/auth/register`

**Verification**: User can log in with valid credentials. Invalid credentials show error message. Session is set correctly.

### Task 4: Logout Route & Auth Guard Decorator
**Type**: implementation  
**Files**: `auth.py`, `utils/auth_helpers.py`

**Route `GET /auth/logout`**:
1. Clear `session` (use `session.clear()`)
2. Flash: "You have been logged out."
3. Redirect to `/`

**Auth guard decorator** (`utils/auth_helpers.py`):
```python
import functools
from flask import session, redirect, url_for, flash, g

def login_required(view):
    @functools.wraps(view)
    def wrapped_view(**kwargs):
        if g.user is None:
            flash('Please log in to access this page.', 'error')
            return redirect(url_for('auth.login'))
        return view(**kwargs)
    return wrapped_view
```

**Load logged-in user before each request** (in `auth.py` or `app.py`):
```python
@app.before_request
def load_logged_in_user():
    user_id = session.get('user_id')
    if user_id is None:
        g.user = None
    else:
        g.user = get_user_by_id(user_id)
```

**Update `base.html` navigation**:
- If `g.user` exists: show "Dashboard" link, user name, and "Logout" button
- If `g.user` is None: show "Login" and "Register" links

**Verification**: Unauthenticated users are redirected to login when accessing protected pages. Logout clears the session. Navigation updates correctly based on auth state.

### Task 5: Auth Flow Integration Testing & Polish
**Type**: verification + styling  
**Files**: Multiple templates, `static/css/style.css`

Final integration tasks:

1. **Flash message styling refinement**: Ensure success (green), error (red), and warning (amber) flash messages render correctly with icons and auto-dismiss animation

2. **Form validation UX**:

   - Style invalid input borders on submission error

3. **Redirect after login**: After successful login, if user was redirected from a protected page, return them to the originally requested URL (using `next` query parameter)

4. **Security hardening**:
   - Set `session.permanent = True` with a reasonable lifetime (e.g. 7 days)
   - Configure `SESSION_COOKIE_HTTPONLY = True` and `SESSION_COOKIE_SAMESITE = 'Lax'` in config

5. **Manual test walkthrough**:
   - Register a new user → success message → redirected to login
   - Log in with correct credentials → welcome message → see logged-in nav
   - Visit a protected route without auth → redirected to login with message
   - Log out → session cleared → nav shows Login/Register
   - Attempt registration with duplicate email → error message
   - Attempt login with wrong password → error message

**Verification**: All 6 manual test scenarios pass.

## Success Criteria

1. User can register with name, email, and password; validation errors are shown for invalid input
2. Passwords are hashed with Werkzeug's `pbkdf2:sha256` before database storage
3. User can log in and log out; session correctly stores and clears `user_id`
4. `@login_required` decorator blocks unauthenticated access and redirects to login
5. Navigation bar dynamically shows Login/Register OR Dashboard/Logout based on auth state
6. Complete data isolation — all user queries filter by session `user_id`
