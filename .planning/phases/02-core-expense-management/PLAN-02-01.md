# Plan 02-01: Expense CRUD Routes, Database Helpers & Interactive Forms

**Phase**: 2 — Core Expense Management & Export  
**Plan**: 02-01  
**Requirements**: EXP-01, EXP-03, EXP-04  
**Estimated tasks**: 4

## Objective

Build the complete backend and frontend for expense recording and mutation: database queries with strict per-user isolation, the `expenses` Flask Blueprint, Add and Edit expense form views with currency prefix and date defaults, and secure expense deletion with confirmation.

## Context

- Strict multi-tenant user isolation: every query on `expenses` MUST include `WHERE user_id = ?` to prevent cross-account data leakage.
- Amounts must be validated as positive numbers (`amount > 0`).
- Date format must follow `YYYY-MM-DD` and default to the current date if not provided.
- Category selection maps directly to foreign key `category_id` referencing `categories.id`.
- Reusable form template for both `Add` and `Edit` modes to maintain DRY principles.
- Deletions must occur via `POST /expenses/<id>/delete` (not GET) to prevent accidental deletions via crawlers or URL prefetching.

## Tasks

### Task 1: Expense Database Helpers & Validation
**Type**: implementation  
**Files**: `utils/expense_helpers.py`

Implement database access layer ensuring complete user isolation:
- `get_categories()`: Fetches all categories ordered by name (`[{'id': ..., 'name': ...}]`).
- `create_expense(user_id, category_id, amount, expense_date, note=None)`: Validates positive amount, valid date, and category existence; inserts record into `expenses`; returns new expense ID.
- `get_expense_by_id(expense_id, user_id)`: Fetches a single expense record matching both `id = ?` and `user_id = ?`. Returns `None` if not found or unauthorized.
- `update_expense(expense_id, user_id, category_id, amount, expense_date, note=None)`: Validates and updates the existing expense record where `id = ?` AND `user_id = ?`.
- `delete_expense(expense_id, user_id)`: Deletes the record matching both `id = ?` AND `user_id = ?`. Returns boolean indicating whether a row was deleted.

**Verification**: Unit tests verify creation, retrieval, updates, and verify that User B cannot read or delete User A's expense.

### Task 2: Expenses Blueprint & CRUD Endpoints
**Type**: implementation  
**Files**: `expenses.py`, `app.py`

Create `expenses_bp = Blueprint('expenses', __name__, url_prefix='/expenses')`:
- `@expenses_bp.before_request`: Require login for all routes in blueprint via `@login_required`.
- `GET /expenses/add`: Renders form pre-populated with today's date and list of categories.
- `POST /expenses/add`: Validates form inputs (`amount`, `category_id`, `expense_date`, `note`), persists expense, flashes success ("Expense of ₹{amount} added successfully!"), and redirects to expense list.
- `GET /expenses/<int:id>/edit`: Fetches expense ensuring `user_id` ownership; renders form pre-populated with existing data; returns 404 if not found.
- `POST /expenses/<int:id>/edit`: Validates modified fields, updates DB, flashes success ("Expense updated successfully!"), redirects to list.
- `POST /expenses/<int:id>/delete`: Validates ownership, deletes record, flashes confirmation ("Expense deleted successfully."), redirects to list.

Register `expenses_bp` in `app.py`.

**Verification**: All routes register properly in Flask and handle both valid submissions and validation rejections.

### Task 3: Interactive Add / Edit Expense Template
**Type**: frontend + UI  
**Files**: `templates/expenses/form.html`, `static/css/style.css`

Create a clean, responsive form template:
- Extends `base.html`.
- Dynamic page title and heading: "Add New Expense" or "Edit Expense".
- Amount input with static Indian Rupee (`₹`) symbol badge prefix and step `0.01`.
- Category dropdown `<select>` populated from categories table with visual icons or styled options.
- Date input with HTML5 `type="date"`, defaulting to today (`YYYY-MM-DD`).
- Notes input / textarea with placeholder (e.g., "Lunch with client, groceries, petrol...").
- Dual action buttons: "Save Expense" (gradient primary) and "Cancel" (secondary outline link).
- Client-side and server-side validation feedback.

**Verification**: Form displays cleanly on both mobile and desktop; inputs bind properly to POST requests.

## Success Criteria

1. Authenticated users can log expenses with amount, category, date, and optional notes.
2. Form fields are strictly validated (positive amount, valid date, valid category).
3. Authenticated users can edit any of their own expenses; attempting to edit another user's expense returns 404/unauthorized.
4. Authenticated users can delete an expense with confirmation.
5. All operations enforce user isolation (`WHERE user_id = ?`).
